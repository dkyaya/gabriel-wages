# Dashboard deployment source mapping

1. A push to `main` touching `docs/dashboard/**` or `scripts/build_dashboard_data.py` triggers `.github/workflows/deploy-dashboard.yml`.
2. The workflow checks out the pushed commit.
3. `python scripts/build_dashboard_data.py` writes generated JSON to `docs/dashboard/data/`.
4. Vite imports those JSON files at build time from `docs/dashboard/src/`.
5. `npm run build` writes the public artifact to `docs/dashboard/dist/` with base path `/gabriel-wages/`.
6. `actions/upload-pages-artifact` uploads `docs/dashboard/dist`.
7. `actions/deploy-pages` deploys that artifact to `https://dkyaya.github.io/gabriel-wages/`.

The public site is not served directly from committed `docs/`, a `gh-pages` branch, or a checked-in `dist/` tree. The build artifact is ephemeral and generated by Actions. `scripts/build_dashboard_data.py` does write the JSON consumed by the deployed app, but before this fix the visible header selected historical scout-phase fields instead of the newer memo/Tier C status fields.

No `.nojekyll` file is required for this Actions artifact path. The Vite base path already matches the GitHub project-site subpath.
